# 快速上手

给你自己（或你的读者）看的 5 分钟指南。

---

## 一、把系统跑起来

需要 **Node.js 18 或更高版本**。不需要 `npm install`——本项目零依赖。

```bash
# 在项目根目录执行
node server/index.mjs
```

终端会打印：

```
  推理小说诡计标签分析与推荐系统
  ────────────────────────────────────────────
  ▸ 访问地址   http://127.0.0.1:8787
  ▸ 种子知识库 257 本（data/books/）
  ▸ 标签字典   70 个标签 / 6 个类别
  ▸ 用户数据   server/data/books.json
  ▸ 反剧透校验 已启用（服务端 + 前端双层）
```

用浏览器打开 `http://127.0.0.1:8787` 即可。

> **Windows 用户注意**：如果 `npm start` 报「禁止运行脚本」，那是 PowerShell 的
> 执行策略拦住了 `npm.ps1`，与本项目无关。直接跑 `node server/index.mjs` 即可。

> **不想装 Node？** 把 `web/` 和 `data/` 一起丢到任意静态托管（GitHub Pages 等）也能用，
> 只是新增的书存在浏览器本地。但**不能直接双击 `index.html`**——
> `file://` 协议下浏览器会拒绝加载 ES Module。

## 二、最常用的一条路径：查一本书

1. 打开首页「**诡计分析**」
2. 左侧搜索框输入书名（试试「**无人生还**」），点击结果
3. 右侧立即生成报告，包含：
   - **诡计标签**：这本书有哪些类型的诡计（密室？叙述性诡计？童谣杀人？）
   - **3 部相似作品**：诡计机制最接近的书，附匹配理由
   - **平台评价参考**：豆瓣 / 虎扑 / Goodreads 的评分与去剧透摘要
   - **阅读提示**：该留意什么（只给维度，不给答案）
4. 点「**复制 Markdown**」直接粘贴到任何笔记软件

**全程不会被剧透。** 页面右侧还有「安全自检清单」，可以展开看系统逐条确认的结果。

## 三、查知识库里没有的书

1. 首页切到「**输入新作品**」
2. 填书名 + **无剧透梗概**（只写设定和悬念，别写凶手和结局）
3. 系统会从梗概里推断候选标签，每个标签旁边标了「明确」或「可能」，并显示命中的原文
4. 核对、勾掉不准确的，点「生成分析报告」
5. 想留下来，点报告上方的「**存入知识库**」

> 梗概请控制在 **100 字以内**，超出会被拦截——这是需求规范的硬性要求。

---

## 四、自己添加一本书

「**添加小说**」页，左边填基础信息和平台评分，右边选标签、写简介和阅读提示。

- 表单会**实时体检**：写了带剧透的内容会立刻标红并阻止提交
- 「**谜底保险库**」区块是可选的，写进去的内容**永远不会出现在任何界面、报告或导出文件里**
- 没有把握的评分就留空，报告里会显示「暂无数据」——**编造评分比没有评分更糟**

---

## 五、想搞明白"为什么推荐这本"

「**作品对比**」页选两部书，能看到：

- 加权相似度百分比
- 每个标签类别下**共享了哪些、各自独有哪些**
- 算法三项分量的拆解（加权重合度 / 加权杰卡德 / 稀有度）

也可以在看报告时展开「**匹配明细**」——推荐 3 本书的理由都在那里。

## 七、给维护者：改完数据要跑什么

```bash
npm run check     # 反剧透体检（会报告任何可能泄底的表述）
npm test          # 87 项单元测试
npm run build     # 五道门禁全跑 + 生成 manifest
npm run ratings:update   # 更新平台评分（抓取 → 校验 → 写回）
```

> 在 Windows 上如果 npm 脚本报「禁止运行脚本」，
> 把上面每条 `npm run X` 换成 `node scripts/X.mjs` 也一样能跑
> （例如 `npm run build` → `node scripts/build.mjs`）。

`npm run check` 是硬门禁：只要有作品被判定为高危泄底，退出码就是 1，适合挂到 CI 上。

## 八、遇到问题

**页面空白，控制台报 `Failed to load module script`**
→ 你在用 `file://` 打开。请用 `node server/index.mjs` 或 `npx serve .`。

**顶部显示「本地模式」**
→ 没检测到后端。数据存在浏览器里，清缓存会丢。跑 `node server/index.mjs` 切成服务器模式。

**添加的书在别的电脑上看不到**
→ 本地模式下数据不共享。用服务器模式，或导出 JSON 再在另一台导入。

**报告里的豆瓣评分和我看到的不一样**
→ 知识库中 **1040/1217 部**的豆瓣评分是**实时抓取**的，报告里带「来源链接」，
可以点进去核对；46 部没抓到（其中一部分豆瓣上检索不到、一部分条目存在但尚无评分），
直接标注「暂无数据」，另有 2 部保留离线估计并在报告里显式标注，
请以平台为准。

> 报告第五部分用 🟢 / 🟡 / ⚪ 三个色点标出每条评分的来源等级：
> 🟢 实时抓取、🟡 离线估计（未联网核实）、⚪ 暂无数据。
> 另有 116 部因评价人数不足 200 会被附加「⚠ 评价人数偏少，样本不足」。

想让评分更新到最新，运行：

```bash
npm run ratings:update     # 抓取 → 校验 → 写回，一条命令
```

**为什么虎扑和 Goodreads 都是「暂无数据」**
→ 虎扑没有成体系的书籍评分；Goodreads 在当前网络环境不可达（无公开 API 且直连超时）。
系统遵循「不得编造」原则，抓不到就写「暂无数据」，不会填一个看起来合理的数字。
