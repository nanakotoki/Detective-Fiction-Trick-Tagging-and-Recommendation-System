# 宝塔面板路线（替代 `步骤手把手.md` 里的 B6）

> **什么时候用这一份**：服务器上已经装了宝塔面板（`/www/server/panel` 存在），
> 也就是 80 端口已经被宝塔的 Nginx 占着。这种情况下**不要装 Caddy**——
> 两个程序会抢 80/443，谁也起不来。改用宝塔自己的「站点 + 反向代理 + 一键 SSL」，
> 效果完全一样（HTTPS、HTTP 跳转、访问密码、安全头都由 Node 提供，宝塔只做转发）。
>
> **A 段、B0–B5、B7 全部不变**，只有 B6 用本文替换。

---

## 铁律：宝塔只做「转发」，绝对不能自己发文件

整站（包括 `web/` 前端、`/data/books/*.json`、封面图片）**全部**要转发给
`127.0.0.1:8787` 由 Node 处理。一旦让 Nginx 自己去读文件：

- `data/books/*.json` 里的 **3420 条谜底**会直接出网（Node 的剥皮逻辑被绕过）；
- CSP / X-Frame-Options / CSRF 这些防线全部失效；
- 页面的 `/data/...` 请求会被当成静态文件，可能 404 导致卡在「加载中…」。

所以：**站点根目录 `/www/wwwroot/tokei-detective.top` 里不要放任何项目文件**（保持空目录即可）。

---

## 第一步 🖥️ 确认 Nginx 在跑（浏览器 · 宝塔面板）

面板左侧 **软件商店 → 已安装**，确认 **Nginx** 状态是「运行中」。
没有的话在「软件商店」里装 Nginx（编译安装或极速安装都行，版本随意）。

## 第二步 🖥️ 添加站点（浏览器 · 宝塔面板）

左侧 **网站 → 添加站点**：

| 项目 | 填什么 |
|------|--------|
| 域名 | `tokei-detective.top`（如果解析了 `www`，再按回车加一行 `www.tokei-detective.top`） |
| 根目录 | 保持默认 `/www/wwwroot/tokei-detective.top` |
| FTP | **不创建** |
| 数据库 | **不创建**（选「不创建」） |
| PHP 版本 | **纯静态** |

点「提交」。

## 第三步 🖥️ 加反向代理（浏览器 · 宝塔面板）

**网站 → 点站点名 → 反向代理 → 添加反向代理**：

| 项目 | 填什么 |
|------|--------|
| 代理名称 | `trick` |
| 目标 URL | `http://127.0.0.1:8787` |
| 发送域名 | `$host` |
| 缓存 | **关闭** |

保存。此时浏览器打开 `http://<服务器公网IP>/` 应该已经能看到知识库首页了
（还没有 HTTPS、还没有密码，属于中间状态）。

## 第四步 🖥️ 删掉会“抢走”图片请求的规则（**最关键，不做封面会 404**）

宝塔的站点模板里自带这两段「图片/静态资源走本地文件」的规则，
**正则 location 的优先级高于反代的 `location /`**，于是 `/covers/xxx.jpg`
不会转发给 Node，而是去站点目录里找文件 → 找不到 → 404。

**网站 → 站点设置 → 配置文件**，找到下面两段，**整段删掉**（或在每行前加 `#`）：

```nginx
location ~ .*\.(gif|jpg|jpeg|png|bmp|swf)$
{ expires 30d; error_log /dev/null; access_log /dev/null; }
location ~ .*\.(js|css)?$
{ expires 12h; error_log /dev/null; access_log /dev/null; }
```

保存（宝塔会自动 `nginx -t` 并重载）。**如果保存时报语法错误，别自己改，把红字贴给我。**

> 为什么必须删：本站 3846 张封面存在 `web/covers/`，其中 116 张是 `.jpg`、
> 3730 张是 `.webp`。`.webp` 不在上面规则里所以没事，`.jpg` 会全军覆没——
> 表现就是「有的封面是图、有的封面是裂图」，很难查。

## 第五步 🖥️ 确认反代把真实协议传给了 Node

**站点设置 → 反向代理 → 点 `trick` 右侧「编辑」→ 配置文件**，内容里应当有这四行：

```nginx
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
```

缺哪行补哪行（尤其 `X-Forwarded-Proto`：Node 靠它判断「外部是 HTTPS」，
缺了就不发 HSTS；CSRF 的同源判断也会失准）。保存。

## 第六步 🖥️ 一键 HTTPS（浏览器 · 宝塔面板）

**站点设置 → SSL → Let's Encrypt**：

1. 勾选 `tokei-detective.top`（以及 `www` 那条）；
2. 验证方式选 **文件验证**；
3. 点「申请」，等十几秒。

成功后把 **「强制 HTTPS」** 打开。

> **申请证书前，先在「站点设置 → 配置文件」里加这一段**，否则文件验证一定会失败：
> 校验文件既会被反向代理吞掉（表现为 **404**），又会被第七步的密码保护挡住（表现为 **401**）。
>
> ```nginx
> location ^~ /.well-known/acme-challenge/ {
>     root /www/wwwroot/tokei-detective.top;
>     auth_basic off;
>     allow all;
> }
> ```
>
> 保存后再点「申请」。（`^~` 前缀匹配优先级高于正则 location，能确保校验文件由 Nginx 直接返回、
> 且不要求密码。）证书签下来之后这段可以留着，续期还要用。

## 第七步 🖥️ 加访问密码（替代 Caddyfile 里的 basic_auth）

### ⚠️ 先别用面板里的「添加加密访问」

宝塔站点设置里那个 **「加密访问」**（要填"目录 / 名称 / 用户名 / 密码"的对话框）
**不能用于本站**：它是**目录级**的，会生成一条优先级高于反向代理的 `location` 规则，
对整站反代来说等于把站打瘫（对话框自己也写了「会导致目录及子目录下的反向代理失效」）。

### 正确做法：把校验挂在 `server { }` 级别（两步）

**① 生成密码文件**（服务器上执行；`openssl` 自带的 apr1 哈希 nginx 认）：

```bash
sudo mkdir -p /etc
HASH=$(openssl passwd -apr1 '你的密码')
echo "tokei:$HASH" | sudo tee /etc/tokei-archive.pass
```

**② 站点设置 → 配置文件**，在 `server_name ...;` **下面**加两行，保存：

```nginx
    auth_basic "tokei";
    auth_basic_user_file /etc/tokei-archive.pass;
```

以后改密码：重跑 ① 覆盖同一个文件即可，nginx 立刻生效（**不用重载**）。

### ⚠️ 密码文件必须放在 `/etc`，不能放宝塔的 `vhost` 目录下

实测踩过的坑：放在 `/www/server/panel/vhost/nginx/pass/` 会得到这样的组合——

| 现象 | 原因 |
|------|------|
| 不带密码 → **401** | 配置生效了 |
| 带密码 → **500**（nginx 错误页） | worker 读不到密码文件 |

错误日志里是 `open() ".../tokei.pass" failed (13: Permission denied)`，而 `namei -l` 显示：

```
drw------- root root vhost      ← 宝塔把 /www/server/panel/vhost 收成了 700，只有 root 能进
```

文件本身是 644 也没用——**目录不让穿**。nginx worker 以 `www` 身份运行，所以密码文件要放在
`/etc/`（任何进程都读得到）这类位置上。

### 验收（从外网测，四项都要对）

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://<IP>/                                  # 401
curl -s -o /dev/null -w '%{http_code}\n' -u tokei:密码 http://<IP>/                     # 200
curl -s -o /dev/null -w '%{http_code}\n' http://<IP>/api/health                        # 401
curl -s -o /dev/null -w '%{http_code}\n' http://<IP>/covers/<真实文件名>.jpg            # 401
```

带错密码也必须是 401；`WWW-Authenticate: Basic realm="tokei"` 这一响应头在，浏览器才会弹框。

> 注意：上了密码之后，**Let's Encrypt 的文件验证会被 401 挡住**（见第六步的
> `auth_basic off;` 补丁），签证书前务必先加。

## 第八步 🐧 自查（服务器终端）

```bash
cd /srv/trick-archive && node deploy/check-deploy.mjs tokei-detective.top 用户名:密码
```

**预期**：最后一行 `失败 0 项`。它会验：接口活着、**谜底没有出网**、跨源写被拒、
CSP 等安全头在位、HTTP 跳 HTTPS、证书有效期、封面目录可用、版本一览可取。

> 站点开着整站密码时**必须带上凭据**（否则每一条都是 401）；撤掉密码之后就不用带了。

## 从「整站密码」走到「对外公开 + 令牌写入」

站点要开放给读者时，**不要只把两行 `auth_basic` 删掉**——那样写接口（新增／修改／删除）
就对全世界开放了，任何人 `curl -X POST` 都能往共享书库灌垃圾。
正确顺序是：**先开令牌写入，再撤整站密码**（服务端逻辑见 `server/lib/write-guard.mjs`）。

### ① 服务器上生成令牌（令牌永远不进仓库）

```bash
sudo bash -c 'echo "TRICK_ADMIN_TOKEN=$(openssl rand -hex 24)" > /etc/trick-archive.env'
sudo chmod 600 /etc/trick-archive.env
sudo cat /etc/trick-archive.env      # 把这串令牌抄进密码本
```

### ② 让服务读到它

把仓库里新的 `deploy/trick-archive.service` 覆盖到 `/etc/systemd/system/`
（第 197 轮版本多了一行 `EnvironmentFile=-/etc/trick-archive.env`），然后：

```bash
sudo systemctl daemon-reload && sudo systemctl restart trick-archive
curl -s localhost:8787/api/health      # 期望看到 "writeMode":"token"
```

### ③ 撤掉整站密码

站点设置 → 配置文件，删掉这两行（**只删这两行**，别动别的）：

```nginx
    auth_basic "tokei";
    auth_basic_user_file /etc/tokei-archive.pass;
```

保存。此刻站点对所有人开放，但**写接口仍然要令牌**。

### ④ 验证

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://<域名>/              # 200（不再是 401）
curl -s -o /dev/null -w '%{http_code}\n' -X POST -H 'content-type: application/json' \
     -d '{}' http://<域名>/api/books                                  # 401（要令牌）
node deploy/check-deploy.mjs <域名>                                  # 撤了密码就不用带凭据
```

### ⑤ 你自己怎么加书

浏览器打开站点 → 导航里会多出「添加小说」→ 第一次保存时弹窗要令牌 → 粘上 ① 那串。
令牌只存在**你自己那台浏览器**里，换设备要重输一次；要清掉就点弹窗里的「清除已保存的令牌」。

### 只读模式（暂时不想开写）

什么都不用配：`NODE_ENV=production` + 没有令牌 = **只读**。访客看不到「添加小说」与「编辑／删除」，
`/api/books` 的写请求一律 403，其余功能完全不受影响。

> ⚠️ 公开之后站点会被搜索引擎收录。如果你想避免，告诉我，我加一个只放行特定路径的 `robots.txt`。

## 第九步 🖥️ 把宝塔本身锁起来（站点上线后立刻做）

面板挂在公网 `8888` 上 = 全世界扫描器的头号目标。**软件商店能装一个插件就装一个**
（如「堡塔防爆破」），并至少做这三件事（**面板 → 设置**）：

1. **改面板端口**：换成一个随机高位端口（例如 `38421`），别用 8888；
2. **绑定访问 IP / 开面板 SSL**：只允许你自己的宽带 IP；
3. **别让面板和 SSH 用同一个密码**。

同时去 **阿里云控制台 → 安全组**：`8888`、`888`、`6185`、`6099`、`6195`、`6199`
这些端口**一律不要**对 `0.0.0.0/0` 开放；只放行 `80`、`443`（和必要时限定来源 IP 的 `22`）。

另外：如果装过 **Nginx 免费防火墙 / WAF**，先确认它没有拦截 `/api/**`；
被拦的表现是接口 403/跳转，`check-deploy.mjs` 会有红项。

## 以后怎么更新已部署的站点（属主已交给 `trick` 之后）

第 196 轮把 `/srv/trick-archive` 收成了 `trick:trick` 750/640，所以 **`admin` 不能再直接往里面 scp**
（这正是那次收紧的目的）。更新走「传到 /tmp → 用 root 拷进去」：

🖥️ **Windows**（只传改动的目录，别重传 63 MB 的 `web/covers/`）：

```powershell
ssh admin@<服务器IP> "mkdir -p /tmp/trick-update"
scp -O -r server scripts deploy web/js web/css admin@<服务器IP>:/tmp/trick-update/
```

🐧 **服务器**：

```bash
sudo cp -rT /tmp/trick-update/server  /srv/trick-archive/server
sudo cp -rT /tmp/trick-update/scripts /srv/trick-archive/scripts
sudo cp -rT /tmp/trick-update/deploy  /srv/trick-archive/deploy
sudo cp -rT /tmp/trick-update/js      /srv/trick-archive/web/js
sudo cp -rT /tmp/trick-update/css     /srv/trick-archive/web/css
sudo chown -R trick:trick /srv/trick-archive
sudo find /srv/trick-archive -type d -exec chmod 750 {} +
sudo find /srv/trick-archive -type f -exec chmod 640 {} +
sudo rm -rf /tmp/trick-update
sudo systemctl restart trick-archive
curl -s localhost:8787/api/health      # 起来了吗
```

> `cp -rT` 的 `-T` 是"把目标当目录合并"，不加的话会把 `server/` 塞进 `server/server/` 里。
> 前端是静态文件，**改完只需重传，不用重启**；只有改了 `server/` 里的代码才需要 `systemctl restart`。

## 出问题速查

| 现象 | 原因 / 处理 |
|------|-------------|
| 502 Bad Gateway | Node 没跑：`sudo systemctl status trick-archive --no-pager` |
| 页面一直「加载中…」 | `/data/books/*.json` 被 Nginx 静态处理或 404 → 检查第四步 |
| **只有部分封面裂图（.jpg 那批）** | 第四步的图片规则没删干净 |
| 打开是宝塔默认页 / 别的站 | 域名解析没生效，或站点 `server_name` 里没加这个域名 |
| 证书申请失败 | 80 端口没通、DNS 没生效，或需要第六步的 `^~ /.well-known` 段 |
| 安全头缺失（check 报错） | 反代没传 `X-Forwarded-Proto`；或 Nginx 里另外 `add_header` 覆盖了 |
| 想临时停掉整个站 | 宝塔：**网站 → 站点 → 停用**；或 `sudo systemctl stop trick-archive` |
