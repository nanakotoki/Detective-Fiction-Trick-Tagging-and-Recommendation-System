# 手把手部署清单（照抄即可）

> 给 `tokei-detective.top` + CentOS 8 这台机器写的。**每一段都标了在哪个窗口跑**：
>
> - 🖥️ **A 段**：你自己的 Windows 电脑（CMD 或 PowerShell，在仓库目录里）
> - 🐧 **B 段**：服务器（你已经登进去的那个 `[admin@iZ…]$` 窗口）
>
> 三条铁律：
> 1. **一段一段来**，一段做完看到我说的"预期"再进下一段；
> 2. 命令里凡是 `<尖括号>` 的都要换成你自己的值（我在旁边标了怎么拿）；
> 3. **哪一段报错就把那段的原文贴给我**（连同它的编号，例如 B4），我按报错改。

准备四个窗口/入口：

| 窗口 | 用来做什么 |
|------|-----------|
| ① 电脑上的 CMD/PowerShell | A 段的命令 |
| ② 浏览器：GitHub 仓库页 | 改私有、加 Deploy key |
| ③ SSH 窗口（服务器） | B 段的命令 |
| ④ 浏览器：域名服务商 + 云控制台 | 加 A 记录、放行安全组 |

## 🖥️ A 段：电脑上（2 步）

### A1. 把仓库改成私有（浏览器 ②）

仓库页 → **Settings** → 左侧 **General** → 拉到最下面 **Danger Zone** →
**Change repository visibility** → **Change to private** → 按提示输入仓库名确认。

**预期**：仓库名旁边出现 `Private` 标签。

> 为什么必须先做：这个仓库现在是 public，而你要推的提交里有 `data/books/*.json`
> 的 **3420 条谜底**（凶手／核心诡计／结局）。改成私有之后再推，之前什么都没泄。

### A2. 推送（窗口 ①）

```cmd
cd /d C:\Users\时嘉庆\github\Detective-Fiction-Trick-Tagging-and-Recommendation-System
git push -u origin main
```

**预期**：先出现一堆 `Writing objects: …%`，最后一行是

```
branch 'main' set up to track 'origin/main'.
```

**（约 82MB，慢网几分钟，别中途关窗口。）**

**如果出错**：

| 报错 | 怎么办 |
|------|--------|
| 弹出 GitHub 登录窗 | 正常，登录你的账号即可 |
| `remote: Repository not found` | 私有化之后没权限：确认登录的是 `nanakotoki` 这个账号 |
| `failed to push some refs` | 别慌，把整段输出贴给我 |

## 🐧 B 段：服务器上（7 步，顺序不能换）

### B0. 先自检三件事（窗口 ③）

```bash
whoami && sudo -v && curl -sI https://nodejs.org | head -1
```

**预期**：`admin` / 没有任何输出（说明 sudo 通过）/ `HTTP/2 200`

**如果出错**：`sudo -v` 要密码就输登录密码；`curl` 卡住不动 → 说明这台机器出网有问题，先告诉我。

### B1. 装 Node 与 Caddy（不碰包管理器）

```bash
V=$(curl -fsSL https://nodejs.org/dist/index.json | grep -o '"version":"v22[^"]*"' | head -1 | cut -d'"' -f4)
cd /usr/local && sudo curl -fsSLO "https://nodejs.org/dist/$V/node-$V-linux-x64.tar.xz"
sudo tar -xf "node-$V-linux-x64.tar.xz" && sudo ln -sfn "/usr/local/node-$V-linux-x64" /usr/local/node
sudo ln -sf /usr/local/node/bin/node /usr/local/bin/node && sudo ln -sf /usr/local/node/bin/npm /usr/local/bin/npm
node -v
```

**预期**：最后打印 `v22.` 开头的一行。

```bash
sudo curl -fsSL -o /usr/local/bin/caddy "https://caddyserver.com/api/download?os=linux&arch=amd64"
sudo chmod +x /usr/local/bin/caddy && caddy version
```

**预期**：`v2.` 开头的一行。

> 为什么不 `dnf install`：**CentOS Linux 8 已经 EOL（2021-12 停止维护）**，
> 官方镜像站早就下线，`dnf install` 大概率报 404。用官方二进制完全不依赖它。

### B2. 看服务器有没有 git

```bash
command -v git && git --version || echo '这台机器没有 git'
```

**预期**：要么打印 `git version 2.x`，要么打印 `这台机器没有 git`（`command -v` 是瞬时的，
**不会卡住**；如果你 `dnf` 卡住了，先按 `Ctrl+C` 中断——见下面的说明）。

**没有 git 时，二选一：**

```bash
# 兜底 A：把 yum 源指到归档站，再装 git（推荐）
#   ⚠️ CentOS 8 的仓库文件里用的是 **metalink**（不是 mirrorlist），
#      而 metalink 指向的 mirrorlist.centos.org 早已下线——只注释 mirrorlist 是不够的，
#      dnf 会卡在反复重试上，看起来像「没反应」。下面这行两样都注释掉：
sudo sed -i -e 's/^metalink=/#metalink=/' -e 's/^mirrorlist=/#mirrorlist=/' \
  -e 's|^#baseurl=http://mirror.centos.org|baseurl=http://vault.centos.org|' \
  /etc/yum.repos.d/CentOS-*.repo
sudo dnf -y --setopt=timeout=20 install git --nogpgcheck
git --version
```

> 如果 `dnf` 还是长时间不动（超过 1 分钟没有任何输出）：按 `Ctrl+C` 中断，
> 改走下面的兜底 B，或直接从你的电脑上传（见兜底 C）。**别让它在那儿干等**。

```bash
# 兜底 B：干脆不用 git（需要一个 GitHub 只读 token：
#   网页 → Settings → Developer settings → Fine-grained tokens → 只勾 Contents: Read）
TOKEN=<你的token>
sudo mkdir -p /srv && sudo chown "$USER":"$USER" /srv
mkdir -p /srv/trick-archive && cd /srv/trick-archive
curl -fsSL -H "Authorization: Bearer $TOKEN" -o repo.tar.gz \
  https://github.com/nanakotoki/Detective-Fiction-Trick-Tagging-and-Recommendation-System/archive/refs/heads/main.tar.gz
tar -xzf repo.tar.gz --strip-components=1 && rm repo.tar.gz && ls web/index.html
```

🖥️ **兜底 C 的两条命令在「你自己的 Windows 电脑」上跑，不是在服务器窗口里**——
服务器窗口的提示符长这样：`[admin@iZ…]$`；Windows PowerShell 长这样：`PS C:\Users\…>`。
（真的踩过：把这两条粘进服务器窗口，会得到 `-bash: 公网IP: No such file or directory`。）

把 `<公网IP>` 换成**你平时 SSH 登录用的那个 IP**（就是 `ssh admin@…` 里那个）。

```powershell
# ↓↓↓ 这两条在 Windows 的 PowerShell 里跑（开始菜单搜 PowerShell，或在仓库目录 Shift+右键 → 在此处打开 PowerShell）
ssh admin@<公网IP> "sudo mkdir -p /srv/trick-archive && sudo chown admin:admin /srv/trick-archive"
cd C:\Users\时嘉庆\github\Detective-Fiction-Trick-Tagging-and-Recommendation-System
scp -r web data server scripts docs deploy README.md package.json admin@<公网IP>:/srv/trick-archive/
```

> 只传运行需要的目录（`web data server`）+ 配置文件（`deploy` 等），
> **不传** `.git`、`_dd/`（那是本机的工作目录，GitHub 上也没有）。
> 会要你输两次服务器密码，3800 多个文件、约 82MB，慢的话几分钟。

> 走兜底 B 或 C 的话，**B3 整段跳过**（没有 git 就没有 deploy key 这一步），直接进 B4。
> 兜底 C 的代价是以后更新得重新上传；等哪天想用 git 了，再回头做 B2 的兜底 A 即可。

**三条兜底跑完，都用这一段确认代码真的到位了**（进 B4 之前跑一次）：

```bash
cd /srv/trick-archive
ls web/index.html server/index.mjs        # 两个文件都要在
ls data/books | wc -l                     # 预期 243 上下（批次文件数）
du -sh .                                  # 预期 80MB 上下
```

### B3. 配 Deploy Key 并克隆代码

```bash
ssh-keygen -t ed25519 -f ~/.ssh/trick_deploy -N ''
cat ~/.ssh/trick_deploy.pub
```

**把最后打印的那一整行**（`ssh-ed25519 AAAA…` 开头）复制到浏览器 ②：
仓库页 → **Settings** → **Deploy keys** → **Add deploy key** → Title 随便写（如 `ecs`）→
Key 粘进去 → **不要勾** `Allow write access` → **Add key**。

```bash
printf 'Host github.com\n  IdentityFile ~/.ssh/trick_deploy\n  IdentitiesOnly yes\n' >> ~/.ssh/config
chmod 600 ~/.ssh/config
sudo mkdir -p /srv && sudo chown "$USER":"$USER" /srv
git clone git@github.com:nanakotoki/Detective-Fiction-Trick-Tagging-and-Recommendation-System.git /srv/trick-archive
cd /srv/trick-archive && ls web/index.html data/books | head -3
```

**预期**：第一次连 GitHub 会问 `Are you sure you want to continue connecting (yes/no)?` → 输入 `yes`；
克隆完后能看到 `web/index.html` 和几个 `batch-*.json`。

**如果出错**：`Permission denied (publickey)` → Deploy key 没加上（或加到了别的仓库）。

### B4. 建运行用户并起服务

```bash
sudo useradd -r -m -d /srv/trick-archive -s /sbin/nologin trick
sudo chown -R trick:trick /srv/trick-archive
sudo install -d -o trick -g trick /srv/trick-archive/server/data
sudo cp /srv/trick-archive/deploy/trick-archive.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now trick-archive
sleep 1 && curl -s localhost:8787/api/health | head -c 150 && echo
```

**预期**：打印一段 JSON，里面有 `"ok":true` 与 `"bookCount":3420`、`"unreadableFiles":[]`。

**如果出错**：`curl: (7) Failed to connect` → 运行 `sudo systemctl status trick-archive --no-pager`
看红字，把那段贴给我（常见是 Node 路径或权限）。

### B5. 放行端口 + 解析域名（三处都要做）

```bash
# ① 服务器自己的防火墙（CentOS 用 firewalld，不是 ufw）
sudo firewall-cmd --permanent --add-service=http --add-service=https
sudo firewall-cmd --reload
sudo firewall-cmd --list-services      # 预期能看到 http https
```

② **云控制台**（阿里云）：找到这台 ECS → **安全组** → 入方向 → 添加规则：
协议 `TCP`、端口 `80/80` 与 `443/443`、源 `0.0.0.0/0`。（**不要**放行 8787。）

③ **域名服务商**：给 `tokei-detective.top` 加一条 **A 记录**：

| 主机记录 | 记录类型 | 记录值 |
|----------|----------|--------|
| `@` | A | 这台服务器的**公网 IP** |
| `www`（可选） | A | 同上 |

**预期**（在服务器上验证，可能要等几分钟到十几分钟生效）：

```bash
getent hosts tokei-detective.top      # 打印出来的 IP 应当是你服务器的公网 IP
```

### B6. 起 Caddy（HTTPS + 访问密码）

先生成一个密码哈希：

```bash
caddy hash-password --plaintext '<你想设的登录密码>'
```

**复制它打印出的那一整行**（`$2a$14$…` 开头），然后：

```bash
sudo mkdir -p /etc/caddy /var/log/caddy
sudo cp /srv/trick-archive/deploy/Caddyfile /etc/caddy/Caddyfile
sudo cp /srv/trick-archive/deploy/caddy.service /etc/systemd/system/
sudo nano /etc/caddy/Caddyfile
```

在 nano 里把 `<PASTE_HASH_HERE>` 替换成刚复制的哈希（`Ctrl+O` 回车保存、`Ctrl+X` 退出），然后：

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now caddy
sleep 3 && sudo systemctl status caddy --no-pager | head -12
```

**预期**：`Active: active (running)`；再等几秒，浏览器打开 `https://tokei-detective.top`
会**弹出用户名/密码框**（用户名 `admin`，密码是你刚设的），登录后能看到知识库。

**如果出错**：证书签不下来通常是 DNS 还没生效或 80 端口没通——
`sudo journalctl -u caddy -n 40 --no-pager` 看日志，把红字贴我。

### B7. 自查

```bash
cd /srv/trick-archive && node deploy/check-deploy.mjs tokei-detective.top
```

**预期**：11 项全绿，最后一行 `通过 11 项，失败 0 项`。它会验：接口活着、**谜底没有出网**、
跨源写被拒、CSP 等安全头在位、HTTP 跳 HTTPS、证书有效期、封面与版本一览可用。

## 出问题时（速查）

| 现象 | 先看哪里 |
|------|----------|
| 域名打不开、浏览器转圈 | 云控制台**安全组**有没有放行 80/443；`getent hosts 域名` 是否指对 IP |
| 域名打开是别的页面/报备案 | 大陆地域 ECS 需要 **ICP 备案**；先试 `http://<公网IP>:80` 是否通 |
| 502 Bad Gateway | 后端没跑：`sudo systemctl status trick-archive --no-pager` |
| 页面一直「加载中…」 | `curl -s localhost:8787/api/health` 看接口；再看 `journalctl -u trick-archive -n 50` |
| 忘记 Caddy 密码 | 重新 `caddy hash-password` 生成，改 `/etc/caddy/Caddyfile`，然后 `sudo systemctl reload caddy` |
| 想先停掉服务 | `sudo systemctl stop caddy trick-archive` |
